# Конфиденциальность

В текущем коде FkCensor Safari нет собственного сервера аналитики, регистрации, отправки отчётов или формы ввода пароля. Авторизация выполняется самим сайтом Яндекс Музыки в Safari. Скрипт работает внутри страницы музыки и расширения; разрешение на выполнение следует давать только доверенной версии.

## Сетевые запросы

- Сайт Яндекс Музыки обращается к инфраструктуре Яндекса по своим обычным правилам.
- Второй скрипт запрашивает шесть публичных JSON-списков с `raw.githubusercontent.com` при загрузке страницы. При возвращении во вкладку спустя минуту и более выполняется очередная проверка.
- Для ID из базы скрипт загружает указанный MP3 с GitHub или Hugging Face и передаёт его плееру как локальный Blob. Встроенная база сама не содержит музыки.
- В запросах GM к источникам устанавливается `anonymous: true`; скрипт не добавляет пароль, токен Яндекса или заголовок Authorization. Фактическая реализация анонимного запроса зависит от установленного расширения.

Внешние хранилища получают обычные сведения сетевого запроса, в том числе IP, время и путь к списку или аудиофайлу. Путь к аудио может содержать ID записи. Эти сведения нельзя скрыть одной публикацией исходников; проект не обещает сетевую анонимность.

## Хранение на устройстве

Кэш содержит адреса подмен и время обновления. Используется хранилище Userscripts (`GM.getValue` / `GM.setValue`), при его отсутствии — `localStorage` сайта. Код сайта может видеть данные своего `localStorage` и обмен сообщениями в странице. Загруженные аудиофайлы и текущий статус хранятся в памяти вкладки; при закрытии страницы Blob освобождаются. Сам Safari может сохранять сетевой кэш по своим правилам.

Кнопка FK показывает диагностический отчёт локально. Автоматической отправки отчёта автору нет. При ручной публикации отчёта проверьте его текст; не добавляйте сведения об аккаунте и cookies.

## Что не входит в дистрибутив

Профили браузеров, cookies, пароли, файлы состояния рабочего приложения, логи, HAR, скриншоты, локальные настройки, Windows `.exe` и персональная история Git не включены. Состав исходников задан в `public-files.json` и проверяется `npm run audit:public`.

Проверка ищет известные формы секретов и неожиданные файлы. Она уменьшает риск случайной утечки, но не является доказательством отсутствия любых персональных данных. Публиковать следует только подготовленный каталог, с новой историей Git и публичным ником/`noreply` email в коммитах.
