# Публикация

Публикуется только этот подготовленный каталог с `package.json`, `src/` и `public-files.json`. Рабочую папку установленного приложения загружать целиком нельзя. У каталога нет унаследованной истории Git с локальными данными.

## Перед первым открытым релизом

1. Проверить `CREDITS.md`: сопровождающий — vibemashia / obamalolka-oss, соавторы в части списков перечислены отдельно. Для новых соавторов использовать подтверждённые публичные имена.
2. Выбрать лицензию нового кода; если используется код исходного MIT-проекта, сохранить его уведомление. Выяснить условия включения снимка внешних баз; см. `THIRD_PARTY_NOTICES.md`.
3. Выполнить `npm test` и `npm run audit:public`. Открыть список `public-files.json` и проверить состав. Если добавляются файлы, обновить список осознанно.
4. В GitHub → Settings → Emails включить **Keep my email addresses private** и **Block command line pushes that expose my email**. Скопировать свой GitHub-provided `noreply` адрес. См. [инструкцию GitHub](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address).
5. Для первого размещения создать **private** репозиторий, проверить файлы и метаданные коммита, затем сделать public. Приватность репозитория не заменяет очистку его содержимого.

## Git

В терминале открыть именно подготовленный каталог. Ниже указаны публичный ник владельца и адрес GitHub noreply, составленный из публичного ID аккаунта и логина. Перед первым push сверить его с Settings → Emails своего аккаунта.

```sh
git init -b main
git config user.name "vibemashia"
git config user.email "230835576+obamalolka-oss@users.noreply.github.com"
npm test
npm run audit:public
git add -- .
git diff --cached --stat
git diff --cached
git commit -m "Prepare FkCensor Safari 1.0.1"
git log -1 --format=fuller
```

Проверить имя/email в последней команде до push. Изменение `git config` не исправляет уже созданные коммиты. Настройки выше локальны для репозитория, глобальная конфигурация не меняется.

Добавить адрес созданного private-репозитория как `origin`, проверить `git remote -v`, затем отправить `main`. Не включать токен в URL remote или текст команд. Использовать штатный вход GitHub через выбранный клиент.

## Релиз для iPhone

После проверки разместить в GitHub Release архив `FkCensor-Userscripts-1.0.1.zip`, содержащий только `userscripts/` и инструкции/атрибуцию. Сверить состав и SHA-256 с локальным отчётом. Установочные файлы должны совпадать с результатом сборки исходников данного тега.

GitHub Actions в комплекте запускает локальные тесты и аудит. Он не имеет права записи в репозиторий и автоматически ничего не публикует.

Авторы внешних библиотек и данных перечисляются в CREDITS. `Co-authored-by` в коммите используется только для людей, участвовавших в изменении, с выбранным ими публичным/noreply email. Не добавлять чужие email по догадке.
